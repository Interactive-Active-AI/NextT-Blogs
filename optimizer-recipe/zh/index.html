01冻结优化器本身就是仪器的一部分

NextTransformer 比较的是架构。凡是不属于架构的东西都必须按住，否则一次比较衡量的就是调参预算，而不是设计本身。所以优化器由协议钉死，细到每个标量组的 beta 值，而这些钉死的值会被哈希进每份公开结果携带的指纹里。

这把通常的激励倒了过来。一份调过的配方，想成为眼前这个模型的最优配方；一份冻结的配方，想成为在它没见过的模型上最不意外的配方——因为下一个人提交的架构，必须就着它活下去。带着这个前提读代码，好几处原本显得随意的选择就变得可读了。

02两个标量承担迁移

在基础学习率和优化器里的实际学习率之间，隔着两个乘子，它们回答的是两个彼此独立的问题。

两者都写成相对某个参照点的比值，而不是绝对公式，而这个参照点正是当初调出这些学习率的模型：nanochat 的 d12，宽 768，batch 为 219 tokens。这份配方并不声称自己知道任意模型的正确学习率，它声称的是：知道怎么把一个它信得过的学习率，搬到另一个宽度、另一个 batch 的模型上。

协议每步 220 tokens，所以对所有正式运行 bscale 恰好等于 √2，走的是批量平方根规则：batch 翻倍，学习率乘 √2。宽度走的是负二分之一次方，于是宽 1,280 的模型拿到参照值的 0.775 倍，宽 2,048 的拿到 0.612 倍。

03不是一个学习率，是八个

这份配方里并没有「一个带学习率的优化器」，而是八到九组参数，每组有自己的学习率、自己的 betas、自己的 weight decay。表 3 是全部。

表里有三处细节容易被一眼扫过去。

betas 并不共享。词嵌入用 β₂ = 0.995，输出头用 0.96，二阶矩的有效平均窗口差了大约一个数量级。嵌入的梯度是稀疏的——某个 token 的那一行只在这个 token 出现时才被碰到——长窗口是让二阶矩估计可用的唯一办法。输出头每个样本都见到，不需要这个。而 x0 lambdas 干脆把惯例倒了过来：β₁ = 0.96 大于 β₂ = 0.95。

eps 全线取 1e-10，比常见的 1e-8 低四个数量级。eps 极小，意味着即使梯度很小，Adam 也仍然贴近纯粹的符号式归一化，而不会在小梯度区间悄悄退化成 SGD。

smear 门是唯一完全不缩放的学习率：固定 0.2，不随 batch 也不随宽度变化。模型里其他每一组都会随 batch 移动，只有它被钉死——读起来像是在说，这个门的合适学习率是门自身的性质，而不是这次运行的性质。

3.1宽度缩放落在哪里，又没落在哪里

只有三组吃 dscale：输出头、词嵌入和 value embeddings。Muon 不吃，标量不吃，辅助 AdamW 组也不吃。

这条界线恰好画在「按词表索引而非按宽度索引」的参数上——这些矩阵的 fan-in 随模型增长，但每一行拿到的梯度贡献次数并不随之增长。block 矩阵则交给 Muon，它的更新经 Newton–Schulz 迭代正交化，范数因此由迭代本身决定而非由梯度尺度决定。这样读下来，配方是把宽度迁移恰好施加在更新规则本身没有提供它的地方。

3.2每个参数恰好被覆盖一次

各组建完之后，代码会收集所有尚未认领的参数，把二维的按 tuple(p.shape) 分进 Muon 桶、其余的归入标量 AdamW 组，然后断言这些组恰好覆盖模型全部参数一次——不重不漏。

对一个接受外部架构投稿的仓库来说，这条断言在干实事。它要防的并不是崩溃，而是某个新模块的参数悄悄拿到了默认学习率（或者拿到两次），然后在一次谁都不知道配错了的运行上发表结果。按形状分桶则是另一回事：Newton–Schulz 是批量矩阵运算，同形状的矩阵必须一起走。

04weight decay 其实是一个参数量

协议把 weight decay 写成 0.28。没有任何一个参数是按 0.28 衰减的。

这两个常数是 nanochat d12 和 d24 的矩阵参数量。规则来自 nanochat：衰减与矩阵参数量成反比，模型越大，每个参数被衰减得越少。0.28 是以 d12 为单位表达的衰减率，那个比值负责把它换算到真正在训练的模型上。

在 d24 上两者完全一致，这正是这次替换安全的原因：scaling 研究与参照协议在二者重叠之处并不冲突。这是一处很小的工程，作用却不小——一条在尺寸扫描中悄悄改变含义的超参规则，会污染这次扫描本来要测量的那条尺寸曲线。

05同时运行的三条调度曲线

设置调度的只有一个函数，但它让三样东西各走各的曲线。

学习率。40 步线性 warmup，然后持平，最后 65% 的训练线性衰减到峰值的 5%。65% 的 warmdown 按惯例算是很长的：整个运行的大部分时间都花在下坡上，而不是待在顶上。

Muon 动量。前 400 步从 0.85 爬到 0.97，保持 0.97，然后在 warmdown 期间降到 0.90——降的起点与学习率开始下降的边界完全重合。训练早期权重移动最快，此时动量缓冲里装的历史最新；后期学习率衰减，动量不是收紧而是放开，这让有效步长不至于像单看学习率那样塌得那么快。

Muon 的 weight decay。从第 0 步的满值按余弦降到结尾的 0，与学习率曲线彼此独立。正则化在模型还在挑选要表示什么的时候最强，到它开始收敛定形时已经消失。

学习率调度是每个人都会写下来的那条。另外两条，才是协议如果不钉死、两份投稿之间就会无声不同的东西。

06刻意不做的事

这里没有全局梯度裁剪。对一份冻结协议来说这是个有意的立场：全局裁剪是一张安全网，但它同时会在某个架构的梯度比另一个大的时候悄悄重新缩放这场比较，使得不稳定看上去像是调参差异，而不是设计本身的性质。

取而代之的是两处定点裁剪，在梯度累积之后、更新之前，只作用于确实需要的组件——Circle 的 halter 和 loopformer 的 conditioner。两者都是架构专属的控制通路，而非普通权重。这个模式对新投稿同样适用：允许例外，但例外要被命名，并且在预实验之前就登记，而不是在预实验过程中被发现。

07我们还不知道的

在这里坦白边界比平时更重要，因为配方是冻结的，不会为每份投稿重新调过。

基础学习率是在一个模型、一个宽度、一个 batch 上调出来的。两个迁移标量是通行规则，不是在本代码库上做出的测量，而且仓库里目前没有任何东西证明批量平方根规则和宽度负二分之一次方规则在 scaling 研究将要覆盖的整个范围内都成立。T3 跨越宽度 1,024 到 2,048，这是该假设第一次在同一算力预算下被四个点检验——而如果它不成立，表现出来会是尺寸曲线上一段与架构毫无关系的弯曲。

各组的 betas 和 decay 是继承来的，我们没有任何一项的单独消融。混合专家家族的路由系数则被明确标注为预实验设置，而非已登记的配方。

这些都不动摇协议要做的那场比较：每个架构面对的是同一份配方，所以两份结果之间的差异仍然是两种设计之间的差异。它的含义是，这份配方是一个固定下来的选择，而不是一个已被证明的最优解；而尺寸曲线，会是第一个告诉我们这个选择有多好的东西。
